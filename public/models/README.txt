The anatomical skeleton model lives here as:

    skeleton.glb

This is a detailed procedural skeleton generated by
`scripts/generate_skeleton_glb.py` (run it with `python3` + numpy to
regenerate). ~1.78 m tall, feet at y = 0, facing +Z, 173 meshes named to
match the keyword classifier in
`components/anatomy/anatomyMapping.ts`, with `separationOffset` node
extras driving the exploded-joint effect in scroll sections marked
`separate: true`.

To swap in a scanned/licensed anatomical model instead, replace this file
and keep the same conventions:

- Format: glTF binary (.glb), ideally Draco/meshopt-compressed to keep the
  initial load light.
- Scale: the rig is treated as ~1.75m tall, standing at the world origin,
  feet at y = 0, facing +Z. If your model uses a different scale/origin,
  adjust the camera keyframes in components/anatomy/anatomyData.ts (search
  MODEL_SCALE note in AnatomyScene.tsx) rather than rescaling the asset.
- Mesh naming: components/anatomy/anatomyMapping.ts auto-classifies meshes
  into anatomy groups (skull, spine, ribCage, shoulder, arm, hand, pelvis,
  hip, knee, ankle, foot) using keyword matching on mesh names. If your
  model's naming doesn't match, either:
    1. Add patterns to ANATOMY_KEYWORDS in anatomyMapping.ts, or
    2. Pass an `overrides` map into <SkeletonModel overrides={...} />
       listing exact mesh names per group.
  Unmatched meshes still render — they just won't participate in
  region-specific highlighting.

Set NEXT_PUBLIC_USE_PLACEHOLDER_SKELETON=true in .env.local to preview the
full scroll/camera/highlight system with a coarse procedural primitive rig
instead of the GLB.
